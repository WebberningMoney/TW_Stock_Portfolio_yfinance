# 保留兩套獨立的 Corporate Action 重複判斷規則，這次不統一

這個 repo 目前有兩套獨立、規則不同的邏輯決定「同一筆 Corporate Action 有多個來源（yfinance／Yahoo 台灣爬蟲）重複時該保留哪一筆」：`Database.consolidate_duplicate_actions_for_symbol()`（同步時實際合併 SQLite 裡的重複列，tie-break 順序是**完整度優先、來源其次**，且會補齊缺欄位）跟 `dividend_service._dedupe_dividends()`（每次組股利報表時的防禦性二次過濾，tie-break 順序實質上是**來源優先**，完整度幾乎無關緊要，也不補欄位）。這兩套規則在「yfinance 記錄比 Yahoo 台灣爬蟲記錄欄位更完整」這種情境下會給出不同的「保留哪一筆」結果。

2026-09 這次架構工作（把 `Database` 自己的合併邏輯抽成可測試的純函式，見對應 GitHub issue）刻意**不**統一這兩套規則。原因：統一是真正的行為改變（可能讓既有歷史資料在邊界情境下的「保留哪一筆」結果跟現在不一樣），而目前沒有任何測試證明兩套演算法在相同輸入下會給出一致的結果——這個風險跟本次「單純把邏輯搬到可測試的地方、行為完全不變」的精神不成比例。統一應該是未來一個獨立、刻意進行的候選項目，而且開始時應該先用兩邊現有的測試情境當作行為基準來比較，再決定怎麼合併。
